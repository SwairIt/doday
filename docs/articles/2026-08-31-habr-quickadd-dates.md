# «Завтра в 18:00» — это не строка: пять тестов для парсера дат

> Черновик статьи для Хабра.
> Хабы: Python, FastAPI, Тестирование веб-сервисов.
> Автор: Ярослав Боев.

---

В планировщике Doday есть быстрое добавление задач. Пользователь пишет:

```
Сдать реферат завтра в 18:00 !!! @школа
```

Парсер должен вернуть название, срок, приоритет и метку. Но однажды он вернул это:

```python
title = "Сдать реферат в 18:00"
due_at = "2026-05-04T23:59:00+00:00"
priority = "p1"
labels = ["школа"]
```

Время осталось в названии, а «завтра» было вычислено по календарю UTC. Если в Москве уже 00:30, в UTC ещё предыдущий день — задача ошибается на сутки.

Это небольшой баг, но на нём удобно показать пять проверок, которые пригодятся любому парсеру человеческих дат.

## 1. Сначала зафиксируйте ошибку одним тестом

Не подменяйте часы во всём приложении. Передайте текущее время в чистую функцию:

```python
def test_tomorrow_uses_users_timezone() -> None:
    # 3 мая, 21:30 UTC = 4 мая, 00:30 в Москве.
    now = datetime(2026, 5, 3, 21, 30, tzinfo=UTC)

    parsed = parse_quick_add(
        "Сдать реферат завтра в 18:00 !!! @школа",
        now=now,
        timezone_name="Europe/Moscow",
    )

    assert parsed.title == "Сдать реферат"
    assert parsed.due_at == datetime(2026, 5, 5, 15, 0, tzinfo=UTC)
    assert parsed.priority == TaskPriority.P1
    assert parsed.label_names == ["школа"]
```

Почему ожидается 5 мая, 15:00 UTC:

- для пользователя сегодня уже 4 мая;
- «завтра» — 5 мая;
- 18:00 в Москве — 15:00 UTC.

Такой тест проверяет не регулярное выражение, а смысл всей фразы.

## 2. Разделяйте календарную дату и момент времени

`5 мая` и `5 мая в 18:00` — разные типы данных.

У даты без времени нет часового пояса. День рождения, дедлайн «до пятницы» и пункт календаря не должны внезапно переезжать на четверг из-за преобразования в UTC.

У времени встречи, наоборот, есть точный момент. Его удобно хранить в UTC и показывать в зоне пользователя.

Правильная модель выглядит так:

```python
due_date: date | None       # «5 мая», без часового пояса
due_at: datetime | None     # конкретный момент, хранится в UTC
```

В существующей базе Doday используется совместимый вариант: `due_at` плюс флаг `due_date_only`. Это работает как размеченное объединение, но требует дисциплины: значение с `due_date_only=True` нельзя считать обычным моментом времени.

Для срока с часами парсер сначала собирает локальное время, затем переводит его в UTC:

```python
def at_local(day: date, hour: int, minute: int, timezone_name: str) -> datetime:
    timezone = ZoneInfo(timezone_name)
    local = datetime.combine(day, time(hour, minute), tzinfo=timezone)
    return local.astimezone(UTC)
```

Клиент передаёт не смещение `+03:00`, а IANA-имя вроде `Europe/Moscow`. Это важно для зон, где смещение меняется из-за летнего времени.

## 3. «Через месяц» — не «через 30 дней»

В первой версии было удобно написать:

```python
due = today + timedelta(days=30)
```

Но 31 января плюс 30 дней — это 2 марта, а пользователь ожидает конец февраля.

Нужна календарная арифметика с ограничением номера дня:

```python
def shift_months(day: date, months: int) -> date:
    index = day.year * 12 + day.month - 1 + months
    year, zero_based_month = divmod(index, 12)
    month = zero_based_month + 1
    last_day = monthrange(year, month)[1]
    return date(year, month, min(day.day, last_day))
```

Обязательные примеры: 31 января, високосный февраль и переход через декабрь.

## 4. Повтору нужна первая дата

Фраза `тренировка каждый понедельник` раньше давала правило `weekly`, но не давала первый срок. Задача создавалась без даты, а после выполнения следующая не появлялась.

```python
days_ahead = (weekday - today.weekday()) % 7 or 7
first_due = today + timedelta(days=days_ahead)
```

У повторяющейся задачи нужны две части: правило и первая точка отсчёта. Проверяйте обе.

## 5. Не разрешайте `\S+` съедать пунктуацию

Шаблон `@(\S+)` превратит `@магазин,` в метку `магазин,`. Запятая станет частью данных.

Безопаснее явно перечислить разделители:

```python
label_pattern = r"(?<!\w)@([^\s,.;:!?]+)"
```

Здесь полезны тесты не только на запятую, но и на адрес почты: `foo@bar.com` не должен превращаться в метку.

## Короткий чек-лист

Если вы разбираете слова `сегодня`, `завтра` и `через месяц`, проверьте:

- текущее время передаётся в функцию, а не берётся из глобальных часов;
- календарный день вычисляется в часовом поясе пользователя;
- дата без времени не притворяется UTC-моментом;
- локальное время переводится в UTC только после сборки даты и часов;
- месяц считается календарём, а не тридцатью днями;
- у повтора есть первая дата;
- пунктуация не попадает в метки и проекты;
- в тестах есть полночь, конец месяца и переход года.
