# Перечень угроз безопасности персональных данных и принятых мер

Оператор: ФИО оператора, физическое лицо
Информационная система: сайт и веб-приложение getdoday.ru
Утверждено: «___» __________ 2026 г.

Документ составлен во исполнение п. 2 ч. 1 ст. 19 152-ФЗ и требований
постановления Правительства РФ от 01.11.2012 № 1119.

## 1. Характеристика информационной системы

| Параметр | Значение |
|---|---|
| Категория обрабатываемых данных | иные категории персональных данных |
| Специальные категории, биометрия | не обрабатываются |
| Число субъектов | менее 100 000 |
| Субъекты | не являются работниками оператора |
| Тип актуальных угроз | 3-го типа — угрозы, не связанные с недокументированными возможностями системного и прикладного программного обеспечения |
| **Требуемый уровень защищённости** | **четвёртый (УЗ-4)** |

Уровень определён по п. 13 постановления № 1119: иные категории данных,
субъекты не работники, менее 100 000 субъектов, угрозы 3-го типа.

## 2. Угрозы и меры

| № | Угроза | Принятые меры |
|---|---|---|
| 1 | Несанкционированный доступ к учётной записи путём подбора пароля | Пароли хранятся в виде хеша argon2id с солью. Ограничение частоты попыток входа. Минимальная длина пароля. |
| 2 | Использование украденной сессии | Идентификатор сессии подписан ключом приложения, cookie помечена httpOnly, samesite и secure. Смена пароля отзывает все прочие сессии. |
| 3 | Доступ одного пользователя к данным другого | Проверка принадлежности данных выполняется на сервере при каждом обращении, а не в интерфейсе. |
| 4 | Перехват данных при передаче | Обязательное соединение по TLS, принудительное перенаправление с HTTP и заголовок HSTS. |
| 5 | Внедрение постороннего кода на страницы сайта (XSS) | Экранирование пользовательского ввода при выводе, очистка размечаемого текста по белому списку тегов, политика безопасности содержимого. |
| 6 | Выполнение действий от имени пользователя со стороннего сайта (CSRF) | Проверка источника запроса для всех изменяющих операций, cookie с samesite. |
| 7 | Массовая автоматическая регистрация ботами | Подписанная метка времени формы, скрытое поле-ловушка, ограничение числа регистраций с адреса и подсети, проверка существования домена почты. |
| 8 | Внедрение SQL-кода | Все запросы к базе параметризованы средствами ORM; конкатенация пользовательского ввода в SQL не используется. |
| 9 | Компрометация ключей и токенов к внешним сервисам | Токены школьного портала и ключи ИИ-провайдеров хранятся в базе в зашифрованном виде; в интерфейсе и логах не отображаются. |
| 10 | Утрата данных при сбое оборудования | Регулярное резервное копирование базы данных средствами хостинг-провайдера. |
| 11 | Физический доступ к оборудованию | Оборудование размещено в дата-центре хостинг-провайдера на территории РФ; физическая охрана обеспечивается провайдером. |
| 12 | Утечка через машинные носители | Материальные носители персональных данных не используются, распечатки не производятся. |

## 3. Неактуальные угрозы

Угрозы 1-го и 2-го типов (связанные с недокументированными возможностями
системного и прикладного программного обеспечения) признаны неактуальными:
система построена на общедоступном программном обеспечении с открытым
исходным кодом, обработка данных, составляющих государственную тайну, не
ведётся, интерес специализированных нарушителей к системе отсутствует.
